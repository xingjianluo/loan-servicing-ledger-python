# 贷款服务与还款入账（本地可运行）

面向**单个借款账户**的本地贷款账本：生成摊还计划、普通还款入账（含幂等）、
**提前还款申请（两种处理方式、独立入口、独立幂等）**、期间利率调整与
提前还款的穿插保序、逾期判定与状态迁移。纯内存实现，无外部服务、无真实
凭据。金额一律使用**整数“分”**，利息计算使用 `Decimal` + `ROUND_HALF_UP`，
杜绝浮点尾差。

## 运行环境

- Python 3.14+，依赖管理使用 [uv](https://docs.astral.sh/uv/)
- 安装：`uv sync`
- 测试（带输入/中间状态/判定依据打印）：`uv run pytest -s`
- 启动本地 API：`uv run python main.py`，随后访问 <http://127.0.0.1:8000/docs>

## 摊还规则

- 按月还款，月利率 = 年利率 / 12，首期到期日为起借日后一个月（月末自动对齐）。
- **等额本息**：月供 = P·r·(1+r)ⁿ / ((1+r)ⁿ − 1)，先四舍五入到分；
  每期利息 = 上期剩余本金 × 月利率（四舍五入到分），当期本金 = 月供 − 利息；
  **末期本金兜底**为剩余本金，吸收全部累计舍入。
- **等额本金**：每期本金 = P / n（整除基数），**末期吸收本金尾差**；
  每期利息 = 剩余本金 × 月利率。
- 零利率、奇数本金（强制制造尾差）均为支持边界。
- **守恒约束（测试强制校验）**：
  - 每期 本金 + 利息 = 本期应还总额；
  - 累计本金严格等于贷款本金，不存在无法解释的尾差；
  - 等额本息末期月供与平均月供的偏差 ≤ 期数/2 分（每期 ≤0.5 分的舍入累积上界）。

### 利率调整与提前还款后的重算

- **期间利率调整**：仅重算“未到期且完全未还”的期次；已部分还款的当期
  保持原金额（历史已发生的债权债务不追溯修改）。每次调息都记入
  **调息历史**（`rate_history`）：期次按其**到期日**匹配当时已生效的利率。
- **提前还款（独立入口 `POST /prepayments`）**：申请人自选处理方式，
  两种方式最后都把本金摊平——每期“本金+利息=该期应还总额”，计划表内
  本金合计严格等于“贷款本金−累计提前还款”，不存在对不上的零头：
  - **月供不变、缩短期数（`shorten_term`）**：沿用当前每期应还总额
    （等额本息）或每期本金份额（等额本金），求能覆盖剩余本金的最短期数；
    新到期日取原计划**前缀**，缩短后各期到期日逐月衔接，**不产生空期或
    重复期**。若金额小到期数无法真正缩短（只能把末期做小），会明确拒绝
    并提示改用降低月供。
  - **期数不变、降低月供（`reduce_payment`）**：采用**余额法**——提前
    还款即时冲减剩余本金余额，剩余期次在原期数、原到期日上重新摊还，
    跨利率段保持恒定月供，末期吸收累计舍入尾差。
- **反复提前还款**：允许任意次数、两种方式可混用；每次都按**当时真实
  剩余本金**重新计算，本金守恒恒等式始终成立。
- **与调息穿插的语义（关键）**：无论“先调息后提前还”“先提前还后调息”，
  还是多次调息与多次提前还款任意穿插，凡是调息已经生效的未来期次，其
  定下来的适用利率在之后的每一次重算（降月供/缩期）中都**原样保留**，
  不会被按调息前老利率重算。因此同一笔账在相同操作集合下，**最终剩余
  本金、各期金额、利息合计与操作顺序无关**（有专项测试强制校验）。

## 提前还款入口与拒绝原因

提前还款与普通还款是**两个独立入口**，资金不会互相默认转换：

| 入口 | 作用 | 幂等域 |
| --- | --- | --- |
| `POST /payments` | 普通还款，只偿还**当前已到期应还**（罚息→费用→到期利息→到期本金） | `request_id` |
| `POST /prepayments` | 提前还款申请，只冲减**未到期、完全未还**期次的本金 | 独立 `request_id` |

- 普通还款若**超过当期到期应还**：直接拒绝（`PaymentExceedsDueError`），
  **不会默认转成提前还款**；想提前还必须显式调用 `/prepayments`。
- 金额**超过整笔贷款尚未还完的总额**（含提前还款超过未到期剩余本金）：
  `PaymentExceedsTotalError`。两类超额是不同异常、HTTP 同为 422 但
  `error` 字段可区分，调用方可以分别处理。
- **账户已结清**后再次普通还款或提前还款：`AccountSettledError`（409）。
- **金额本身不合法**（0、负数、非整数分）：`InvalidAmountError`（400）。

## 还款分配规则

普通还款入账资金按以下**固定优先级**依次分配（稳定、可预测）：

1. **罚息**
2. **费用**
3. **已到期利息**（到期日 ≤ 还款日，按期号 FIFO）
4. **已到期本金**（同上，按期号 FIFO）

普通还款不触及未到期期次；提前还款只在独立申请中处理本金。
分配恒等式：`罚息 + 费用 + 利息 + 本金 = 还款金额`，支持任意金额的部分还款。

## 幂等与并发

- 普通还款与提前还款各有**独立的申请单号空间与幂等表**：
  - 普通还款 `POST /payments`：同一 `request_id` 重复/并发提交只入账一次，
    回执标记 `duplicate=true`；
  - 提前还款 `POST /prepayments`：同一申请单号重复或并发提交只生效一次，
    即使后一次提交的**金额或处理方式不同**，也只重放首次回执，余额与期次
    不会被重复扣减。
- 账户内部使用同一把线程锁串行化全部写入；普通还款与提前还款混合并发时
  互不串号、各自幂等、总额不重不漏（有 16 线程专项测试）。

## 逾期判定与状态迁移

- 期次状态：`PENDING`（未到期）→ `GRACE`（到期日至到期日+宽限期内）
  → `OVERDUE`（超过宽限期仍未足额）→ `PAID`（足额后任意时点）。
- 账户状态：`ACTIVE` / `OVERDUE` / `SETTLED`；
  - 宽限期内足额还款：不产生罚息，账户保持正常；
  - 宽限期后仍欠：进入 `OVERDUE`，按日计提罚息，
    **逐天**对“当日已过宽限期的未还金额 × 日罚息率”计息（跨宽限期、
    部分还款后基数下降均可正确处理）；
  - 欠款补足（含罚息、费用）后恢复 `ACTIVE`；全部科目结清为 `SETTLED`。
- 每次账户状态迁移都记录 `StatusChange(日期, 原状态, 新状态, 原因)`，可追溯。

## 可配置项（LoanConfig）

| 配置 | 含义 | 默认/示例 |
| --- | --- | --- |
| `principal_cents` | 贷款本金（分，正整数） | `1_000_000_00`（100 万元） |
| `annual_rate` | 年利率（小数，≥0） | `0.036` |
| `periods` | 期数（月） | `12` |
| `method` | `EQUAL_INSTALLMENT` 等额本息 / `EQUAL_PRINCIPAL` 等额本金 | — |
| `start_date` | 起借日（首期到期日 = 次月同日，月末对齐） | — |
| `grace_days` | 宽限期天数 | `3` |
| `penalty_daily_rate` | 逾期罚息日利率 | `0.0005`（万分之五） |

## 失败原因区分（errors.py）

| 异常 | HTTP 状态码 | 触发场景 |
| --- | --- | --- |
| `InvalidAmountError` | 400 | 金额为 0、负数或非整数（普通还款/提前还款均适用） |
| `InvalidRequestError` | 400 | `request_id` 为空、利率为负、本金/期数非法、缩短金额不足以缩期等 |
| `PaymentExceedsDueError` | 422 | **普通还款**超过当期到期应还（不默认转提前还款） |
| `PaymentExceedsTotalError` | 422 | 金额超过整笔未还总额；提前还款超过未到期剩余本金 |
| `AccountSettledError` | 409 | 已结清账户再次普通还款或提前还款 |

> `PaymentExceedsDueError` 与 `PaymentExceedsTotalError` 均继承自
> `ExcessPaymentError`，只需区分“超额大类”时可捕获基类。

## 本地 HTTP API（main.py）

| 方法/路径 | 说明 |
| --- | --- |
| `GET /schedule` | 当前摊还计划（含每期已还/状态/适用利率） |
| `GET /balances` | 各科目未还余额（penalty/fee/interest/principal） |
| `GET /status?as_of=YYYY-MM-DD` | 推进到指定日期的逾期判定与状态迁移历史 |
| `POST /payments` | `{request_id, amount_cents, pay_date}` 普通还款（上限=当期到期应还） |
| `POST /prepayments` | `{request_id, amount_cents, method, apply_date}` 提前还款申请，`method` 为 `shorten_term` / `reduce_payment` |
| `POST /rate-adjustments` | `{new_annual_rate, effective_date}` 利率调整（记入调息历史） |
| `POST /fees` | `{amount_cents}` 计收一笔费用 |

提前还款调用示例（服务启动后）：

```bash
# 1) 普通还款先结清首期
curl -X POST localhost:8000/payments -H 'Content-Type: application/json' \
  -d '{"request_id":"p1","amount_cents":8496726,"pay_date":"2026-02-01"}'

# 2) 提前还 20 万元本金，月供不变、缩短期数
curl -X POST localhost:8000/prepayments -H 'Content-Type: application/json' \
  -d '{"request_id":"pp-1","amount_cents":20000000,
       "method":"shorten_term","apply_date":"2026-02-05"}'

# 3) 同一申请单号再提一次 -> duplicate=true，余额/期次不变
curl -X POST localhost:8000/prepayments -H 'Content-Type: application/json' \
  -d '{"request_id":"pp-1","amount_cents":20000000,
       "method":"shorten_term","apply_date":"2026-02-05"}'

# 4) 调息：自 2026-05-01 起降为年利率 3.0%（已生效未来期次利率被保留）
curl -X POST localhost:8000/rate-adjustments -H 'Content-Type: application/json' \
  -d '{"new_annual_rate":0.030,"effective_date":"2026-05-01"}'

# 5) 普通还款多给 1 分 -> 422 PaymentExceedsDueError，不自动转提前还款
curl -X POST localhost:8000/payments -H 'Content-Type: application/json' \
  -d '{"request_id":"p2","amount_cents":999999999,"pay_date":"2026-03-01"}'
```

## 测试覆盖

`uv run pytest -s`（用例会打印输入、关键中间状态——剩余本金、各期利率与
金额——与判定依据）：

- 两种口径的摊还守恒、尾差归属、零利率、逐期固定利率重算守恒；
- **提前还款两种方式**：降月供（期数/到期日不变、月供下降、本金守恒）、
  缩短期（月供不变、到期日为原序列前缀、期号连续无空期/重复期）、
  金额不足以缩期时的明确拒绝、两种方式反复混用、按当时真实剩余本金重算、
  提前全部结清；
- **调息与提前还款的先后顺序**：先调息后提前还、先提前还后调息两种顺序的
  最终本金/各期金额/利息合计完全一致；两次调息与提前还款穿插时，已生效
  未来期次利率逐期保住（含缩短后的利率前缀）；
- **独立入口与拒绝原因**：普通还款超当期应还直接拒绝且不转提前还款、
  超整笔总额、提前还款超剩余本金、非法金额、结清后两类申请均拒绝；
- **幂等**：普通还款重复/16 线程并发；提前还款重复（含改金额/方式重放）、
  16 线程并发相同申请号、8 普通还款+8 提前还款混合并发不重不漏；
- 跨宽限期逾期、罚息逐天计提、还款后罚息基数下降、逾期后恢复正常、
  罚息→费用→利息→本金的分配顺序；
- HTTP 层 400 / 409 / 422 状态码、错误类型可区分，及 `/prepayments` 幂等。
